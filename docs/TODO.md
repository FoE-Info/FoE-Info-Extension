### Precision of the whole-source pass, measured

54 findings from the math and metadata rules across 599 windows; **6 verified real**, so roughly 11% precision. Two failure modes, both structural rather than fixable by tightening the threshold:

- **`nativeFloats` cannot tell parsing from computing.** Every `msg/` service it flags (`StartupService`, `OutpostService`, `GbDonationService`, `EmissaryService`, `GreatBuildingsService`, `ResourceService`, `BonusService`) is _reading numbers out of an RPC payload_, which is that layer's job. The rule has no exclusion for payload parsing, only for display boundaries.
- **A scoped rule asked everywhere is noise.** `calcPurity` says "modules under `src/js/calc/` are pure"; asking it about `src/js/ui/` produced a p=0.94 false positive on a tooltip builder. Rules now carry an optional `scope` and `auditSource()` drops out-of-scope findings by path, deterministically, before reporting.

Do not read a high `p` as evidence. In the first unscoped run the top finding was `i18nBinding` at **p=0.98** on a window containing only a file header, imports and `createLogger`.

### Second whole-codebase pass (2026-09-26, 462 files / 906 windows)

A second pass widened the target from `src/js` to the whole authored codebase — `src/`, `scripts/`, `tests/`, root config: 462 files, 906 line-aligned windows, all 9 rules, 17.6 s, $0.127 — and paired the rule pass with the metadata pass as §10 asks. Measured, not estimated:

- **The change set is clean; the committed tree is not.** `auditRules()` over the 64 changed paths returned 3 findings, 1 real. `auditSource()` over 906 windows returned 229 after the scope filter. All four items above are still live at their exact recorded lines — re-read during this pass, not carried over.
- **`i18nBinding` cannot carry a whole-tree pass.** 95 of the 145 non-test findings, and the top two are p=0.98 on `armyPanel.js:1-120` and `greatBuildingsPanel.js:411-528` — windows holding a file header, imports and `createLogger`, and no user-visible string at all. Confidence is not merely uninformative here, it is inverted. Real unbound text exists and the rule does surface some of it (`msg/ConversationService.js:153` `<strong>GBG Targets</strong>`, `fn/post.js:237,257,263` `Posting Guild Stats to SS …` / `Guild Stats:` / `Error:`, `ui/playerTooltip.js:181,195,199` `Ignored By:` / `Ignoring:` / `None`), but at window granularity it cannot be separated from the noise. This is the measured case for the deterministic extractor in §10.
- **`calcPurity`'s 4 findings are exactly the 4 files §5 already names** (`goodsTooltipFormatter.js`, `VisitedCityStatsCalculator.js`, `gbNaming.js`, `CityStatsCalculator.js`). A rule that is both scoped and about a literal import reproduces a hand-curated list exactly — the shape a well-formed rule should have.
- **The metadata pass is the one that was silently blind.** `M.metadataStates()` over the 64 changed paths returns **0 candidates** — the same "clean" result recorded three times in §10. Over the 906 source windows it returns **191 candidates → 57 verdicts**, 2 files verified real (the two tables above). That is the whole point of the pairing: the change-set result was never evidence, because `ruleStates()` cannot see committed code.
- **`phantomRpc` is unverifiable by construction.** The index holds 112 captured methods, so a method missing from it is uncaptured, not phantom. Every `phantomRpc` verdict this pass — `ResourceService.getTreasuryBag`, `TimeService.getTime`, `EmissaryService.getOverview` — is a well-known live RPC. Do not report these; the question needs a capture-completeness precondition before it can mean anything.
- **`__touchesDomain` is a probability, not a boolean, and it is not a gate.** It answers true for nothing: mean 0.533 across 906 windows, never exactly 0, ≥ 0.5 on 54% of them. It separates only weakly — 0.698 mean on windows that produced a finding against 0.488 on clean ones — which discards 49% of the clean windows. Read it as a hint, never as a filter.
- **A markdown file is not auditable by a code-rule classifier.** `docs/TODO.md` was judged as a unit of added text like any other path: all 9 rules ≤ 0.10, `nativeFloats` 0.05 — on a document that quotes `Math.ceil(level10Cost * Math.pow(1.025, …))` at line 176. Quoting a violation is not performing one. A green rule audit over prose is a guaranteed false negative, not a clean bill of health.

Two further false-positive classes, both from asking the rule at the wrong granularity: entity-id **dispatch** is not hardcoded metadata — `UnitCalculator.js:40,82,87,92,108` and `CityMapEntityProcessor.js:217,233,250` compare landmark ids but read every value from `entity.bonus?.value` / `mapID.bonus?.value` — and roughly a third of the 57 verdicts are index keys colliding with CSS classes, DOM ids and internal flags (`'red'`, `'green'`, `'incidents'`, `'military'`, `'rogue'`).

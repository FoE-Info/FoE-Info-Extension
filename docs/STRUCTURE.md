# Workspace Structure

```text
FoE-Info-Extension/
├── .agents/
│   ├── agents/                   # 20 canonical flat subagent definitions
│   ├── rules/                    # 17 rules: 8 always-on, 9 model-decided
│   ├── skills/                   # 55 canonical skill packages
│   ├── references/               # Shared profiles, facts, examples, adapters
│   ├── scripts/                  # Harness, Graphify, catalog, and curator tools
│   ├── hooks.json                # Lifecycle hook registration
│   ├── mcp-registry.json         # Canonical task-scoped MCP profiles
│   ├── mcp_config.json           # Generated Antigravity profile
│   └── project.json              # Workspace identity
├── docs/
│   ├── README.md                 # Coordination hub
│   ├── STATUS.md                 # Open work only
│   ├── HANDOFF.md                # Verified resume state
│   ├── SKILLS.md                 # Generated exact skill catalog
│   ├── SUBAGENTS.md              # Generated exact subagent catalog
│   └── plans/ and specs/         # Current implementation/design artifacts
├── graphify-out/                 # Generated graphs; gitignored
├── src/                          # Extension source
├── tests/                        # Node test suites and harness contracts
├── AGENTS.md                     # Portable agent entrypoint
└── package.json                  # Project scripts and metadata
```

## Conventions

- `.agents/` is canonical; host adapters point to it rather than duplicating it.
- Skill and subagent catalogs are generated by `.agents/scripts/generate-agent-catalogs.mjs`.
- Skill entrypoints stay concise; optional depth belongs in owned `references/` with a `references/README.md` catalog.
- Graphify output and worktrees are generated/temporary and remain untracked.
- Runtime game metadata stays network-driven; offline metadata is development input only.
- Standard root documents remain at repository root. Current plans/specifications belong under `docs/`.

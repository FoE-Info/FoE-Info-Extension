# Maintain Graph Knowledge

This skill orchestrates the
[graph-knowledge-explorer](../../agents/graph-knowledge-explorer.md) subagent.
Invoking it requires dispatching that subagent to do the exploration. The main
agent coordinates and verifies delivery; it does not substitute its own
exploration for the subagent.

## Select and dispatch

Default to the current repository, or use whichever repository path/profile the
user explicitly assigns. Here `foe-info` selects this repository and
`metadata-store` selects the sibling folder `../metadata-store/` only when
assigned. Repository targets are separate from upstream Graphify metadata fields
and memory frontmatter.

Read the specialist definition and
[Graph Target Profiles](../../references/agents/graph-targets.md), then dispatch
`graph-knowledge-explorer` with:

- The specialist's full instructions. If the host cannot select a named agent,
  use its subagent tool and supply the definition explicitly.
- The selected repository/source root, graph path and explicit scope. Full graph
  coverage is the default; narrow it only when explicitly assigned.
- The host repository root and local upstream memory/reflection paths. For peer
  investigations, preserve the specialist's host-only persistence policy.
- The requirement to ask and answer architecture questions autonomously, verify
  claims in source, save substantive Q&A and coverage checkpoints through native
  `save-result`, and return reconciled coverage, saved paths and command results.

The subagent owns inventory, traversal, source verification, subsystem tracing,
Q&A persistence and its final reflection. It must continue without waiting for
user-supplied questions or repeated instructions to proceed. The main agent owns
shared documentation and any separately authorized graph refresh, labeling,
exports or model lifecycle; do not assign those operations to the explorer.

If subagent dispatch is unavailable, report that limitation rather than silently
running the exploration in the main agent or claiming the skill completed.

## Reconcile delivery

Check the returned coverage against the complete inventory and inspect saved
memory records. Follow up with the subagent for missing coverage or unsaved
findings until the assigned scope is complete or a concrete limitation remains.
Do not accept a hub sample, a printed inventory or an unsaved chat answer as
whole-graph completion. If interrupted, require a saved resumable checkpoint.

After the explorer finishes, run one final native `reflect` in the host repository
so lessons include all saved results:

```bash
bash scripts/graphify/graphify.sh foe-info reflect --graph graphify-out/graph.json
```

Keep upstream defaults: full Q&A in `graphify-out/memory/`, lessons in
`graphify-out/reflections/LESSONS.md`, and the learning overlay generated by
reflection. Do not create custom or dated findings folders. Reflection summarizes
outcome signals and cited nodes; full answer prose stays in memory.

Report the selected repository, examined/total coverage, unresolved questions,
saved paths and persistence results. Distinguish structural coverage from source
verification and runtime certainty. Review durable conclusions against source
before incorporating them into owning documents under `CONTRIBUTING.md`.
